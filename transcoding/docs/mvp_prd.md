# Clipisode – MVP Product Requirements Document (PRD)

## 1. Overview

Clipisode is a macOS menu bar application that accepts video clip instructions from a browser-based UI via a local WebSocket connection. The app downloads remote video files, trims specified segments, concatenates them into a single MP4 using ffmpeg (x264/x265), and serves the merged output back to the browser for immediate playback.

This MVP targets **direct-download distribution only** (not Mac App Store) and bundles a high-quality ffmpeg build with x264/x265 enabled.

---

## 2. Goals

- Enable a browser page to reliably communicate with a local macOS app
- Allow users to define multiple video segments (URL + start/end)
- Download source files concurrently (max 3 simultaneous)
- Merge segments into a single MP4
- Preview the output immediately in the browser
- Provide clear job status and simple job history (in-memory only)

---

## 3. Non-goals (MVP)

- App Store compliance or sandboxing
- Authentication or authorization
- Persistent job history across restarts
- Cloud upload of outputs
- Multi-job concurrency
- Configurable download concurrency (future setting in app)
- Configurable ports (future setting in app)

---

## 4. Target Users

- Internal users
- Technical creators
- Power users working with hosted video assets

## 6. Local Communication

### WebSocket

- Address: `ws://127.0.0.1:63481`
- Purpose:
  - handshake / availability check
  - job submission
  - progress updates
  - completion notification
  - job cancellation
- Connection limit:
  - Only one active WebSocket connection allowed
  - Additional connection attempts receive `connection_rejected` message and are closed
- Port conflict behavior:
  - If port is in use, app fails to start with clear error message
  - Future: user-configurable port in app settings

### HTTP File Server

- Address: `http://127.0.0.1:63482`
- Purpose:
  - serve merged MP4 files to browser video player
- Scope:
  - Exposes all job outputs (not session-scoped)
  - Note: future versions may add session/token scoping
- Port conflict behavior:
  - If port is in use, app fails to start with clear error message
  - Future: user-configurable port in app settings

## 7. Browser UI Requirements

### Load Behavior

- On page load:
  - Check localStorage for active job state
  - Attempt WebSocket connection
  - If connection fails: show error state
  - If successful and pending job exists in localStorage: send `job_status_request` to check job state
  - If successful and no pending job: show job form

### Job State Persistence (localStorage)

- On job submission:
  - Store `{ job_id, segments, state: "pending", submitted_at }` in localStorage
- On progress updates:
  - Update `state` and `progress` in localStorage
- On job completion or error:
  - Clear active job from localStorage
- On reconnect with active job:
  - Send `job_status_request` message to app
  - App responds with current job state or `job_not_found`

### Job Form

- Dynamic list of segments
  - URL (HTTPS)
  - Start time (seconds, float)
  - End time (seconds, float)
  - Order (drag-to-reorder or explicit field)
- Controls:
  - Add segment
  - Remove segment
  - Reorder segments
  - Submit job

### Playback

- On job completion:
  - Display HTML5 video player
  - Load merged MP4 from local HTTP endpoint
- User may adjust times and resubmit, creating a new job

## 9. Job Lifecycle

### Job ID

- Generated by browser
- Format: UTC timestamp, e.g. `20260115T213045Z`

### File Layout

```
~/Library/Application Support/Clipisode/
  sources/                          # Shared source cache (all jobs)
    <filename>_<size>.mp4           # Deduplicated by filename + file size
  jobs/
    <job_id>/
      temp/                         # Intermediate segment files (deleted on success)
        segment_01.mp4
        segment_02.mp4
      output.mp4
      job.json
```

Note: The `temp/` subdirectory is deleted after successful concatenation. On error, `temp/` is preserved for debugging.

### job.json Contents

```json
{
  "job_id": "20260115T213045Z",
  "segments": [...],
  "state": "done|error|cancelled",
  "started_at": "2026-01-15T21:30:45Z",
  "completed_at": "2026-01-15T21:32:12Z",
  "duration_seconds": 87,
  "error": null
}
```

### Source File Deduplication

- Before downloading, perform HTTP `HEAD` request to get `Content-Length`
- Cache key: `<filename>_<content_length>` (e.g., `video_12345678.mp4`)
- If file with matching key exists in `sources/`, skip download
- If file exists but size differs, download new version with updated key

### Cleanup Policy

- Source files older than 30 days: auto-delete on monthly cron or app launch
- Job folders older than 30 days: auto-delete on monthly cron or app launch

### Behavior

1. Receive `start_job` via WebSocket
2. Change menu bar icon to green
3. Download source URLs (max 3 concurrent, 3 retries per file)
   - Check source cache first (filename + size match)
   - Skip download if cached file exists
4. Trim segments to `temp/` subdirectory using ffmpeg (ordered by `order` field)
5. Concatenate segments into `output.mp4`, delete `temp/` on success (preserve on error)
6. Serve output via local HTTP server
7. Notify browser via WebSocket
8. Change icon back to black

## 10. Transcoding Requirements

### ffmpeg

- Bundled with app
- Built with:
  - x264
  - x265
  - AAC
- Located at:
  ```
  Clipisode.app/Contents/Resources/ffmpeg
  ```

### ffprobe (Optional)

- If bundled, used for pre-flight duration validation
- If not present, app relies on ffmpeg error handling
- Located at:
  ```
  Clipisode.app/Contents/Resources/ffprobe
  ```

### Trimming Strategy (MVP)

- Per-segment trim + transcode (ensures consistent codec):
  ```
  ffmpeg -ss <start> -to <end> -i <input> -c:v libx264 -c:a aac segment_N.mp4
  ```
- Concatenation (stream copy, since all segments are same codec):
  ```
  ffmpeg -f concat -safe 0 -i concat.txt -c copy output.mp4
  ```

Notes:
- Transcode during trim ensures all segments have consistent H.264/AAC codec
- Concat uses `-c copy` (fast, lossless) since segments are uniform
- Frame-accurate cuts due to re-encode

---

## 11. Validation Rules

- URL must be HTTPS
- Start time >= 0
- End time > start time
- Order must be unique positive integer per segment
- Duration validation:
  - If ffprobe bundled: validate end time against source duration
  - If ffprobe not bundled: rely on ffmpeg error handling

## 12. WebSocket Message Contract

### Client → App

**hello**
```json
{
  "type": "hello",
  "client": "clipisode-web",
  "version": 1
}
```

**start_job**
```json
{
  "type": "start_job",
  "job_id": "20260115T213045Z",
  "segments": [
    { "url": "https://example.com/a.mp4", "start": 12.5, "end": 18.0, "order": 1 },
    { "url": "https://example.com/b.mp4", "start": 0, "end": 7.25, "order": 2 }
  ]
}
```

**job_status_request**
```json
{
  "type": "job_status_request",
  "job_id": "20260115T213045Z"
}
```

**cancel_job**
```json
{
  "type": "cancel_job",
  "job_id": "20260115T213045Z"
}
```

### App → Client

**hello_ack**
```json
{
  "type": "hello_ack",
  "app": "Clipisode",
  "version": 1
}
```

**connection_rejected**
```json
{
  "type": "connection_rejected",
  "reason": "Another client is already connected"
}
```

**job_status**
```json
{
  "type": "job_status",
  "job_id": "20260115T213045Z",
  "phase": "downloading|trimming|joining|done|error|cancelled",
  "current": 2,
  "total": 4,
  "message": "Downloading file 2 of 4"
}
```

Notes:
- `phase` indicates current processing stage
- `current`/`total` provide count-based progress (e.g., files downloaded, segments trimmed)
- Client should display progress updates in real-time
- Future: per-file byte progress for granular UI

**job_done**
```json
{
  "type": "job_done",
  "job_id": "20260115T213045Z",
  "output_url": "http://127.0.0.1:63482/jobs/20260115T213045Z/output.mp4"
}
```

**job_error**
```json
{
  "type": "job_error",
  "job_id": "20260115T213045Z",
  "code": "VALIDATION_FAILED|DOWNLOAD_FAILED|FFMPEG_FAILED|PORT_IN_USE|UNKNOWN",
  "message": "End time exceeds duration"
}
```

**job_not_found**
```json
{
  "type": "job_not_found",
  "job_id": "20260115T213045Z"
}
```

**job_cancelled**
```json
{
  "type": "job_cancelled",
  "job_id": "20260115T213045Z"
}
```

## 13. Acceptance Criteria

- Browser page detects app availability
- Only one WebSocket connection allowed at a time
- Job submission triggers:
  - icon color change
  - source download (with cache check, 3 retries)
  - ffmpeg processing
- Browser receives real-time progress updates (phase + count-based)
- Browser receives completion event
- Video plays successfully in browser
- Job can be cancelled mid-progress
- Re-running job with new times works without restart
- Browser reconnect recovers active job state from localStorage
- Source files are deduplicated across jobs
- Files older than 30 days are cleaned up on app launch
- job.json persists final state and duration

---

## 14. Key Risks

- ffmpeg GPL licensing (acceptable for MVP, blocks App Store)
- Large file memory pressure if misconfigured
- HEAD request may not return Content-Length for all servers (fallback: always download)
- Transcode time scales with segment duration and source resolution
